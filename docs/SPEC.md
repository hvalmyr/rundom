# rundom — техническое задание

Веб-приложение для генерации беговых маршрутов по Москве и учёта исследованных улиц.
Исходный прототип: `legacy/begovoj-atlas-moskvy.html`.

## 0. Общие принципы

- Всё считается в браузере, сервера нет. Хостинг — GitHub Pages.
- Персональные данные (треки, отметки, избранное, настройки) хранятся **только на устройстве**:
  треки и геометрия — IndexedDB, настройки — localStorage. Экспорт/импорт резервной копии в JSON.
- Общие (не персональные) данные — сеть улиц и районы внутри МКАД, объекты, справки о районах — собираются
  заранее скриптом и лежат в репозитории как статические файлы; обновляются GitHub Action раз в месяц.
- Полноценная мобильная версия: карта сверху, панель снизу листом (bottom sheet).

## 1. Репозиторий и сборка

- `git@github.com:hvalmyr/rundom.git`, Vite + vanilla JS (ES-модули), без фреймворка.
- Структура: `src/core/` (граф, роутинг, генератор), `src/map/`, `src/ui/`, `src/storage/`, `src/data/`,
  `scripts/` (сборка датасетов из OSM), `public/data/` (готовые датасеты).
- Деплой: GitHub Actions → Pages на каждый push в `main`.

## 2. Дизайн

- Название: **rundom**. Знак — узел грейпвайн из двух шнурков (файл логотипа добавится позже).
- Дизайн-система: «две нити» — **петроль** `#0E5A73` (твоё: пройденное, покрытие, избранное) и
  **кармин** `#B0102C` (впереди: маршрут, главное действие, цели). Полное описание и токены —
  в артефакте дизайн-системы rundom (https://claude.ai/artifact/2Suu33gLxGdB3HrbcNnmjc).
- Нейтрали тёплые, «бумажные»; тёмная тема — тёплая нейтральная, без петрольного оттенка. Зелёного нет нигде.
- Шрифты: Inter (интерфейс), Inter Tight (словесный знак и крупные цифры).
- Темы: светлая, тёмная, авто (по системе). Переключатель в шапке.

### Разделы
- **Маршрут** — генерация.
- **Библиотека** — импортированные треки и избранные маршруты.
- **Прогресс** — карта покрытия, районы, объекты и парки (встречено / исследовал), статистика.
- Вкладки «Места» из прототипа нет: свои точки «пройти через» заменены перетаскиванием маршрута,
  объекты и парки переехали в «Прогресс».

## 3. Генерация маршрута

### 3.0 Дистанция
- Чипы-пресеты дистанций — свои у каждого пользователя, хранятся на устройстве
  (по умолчанию 5 / 10 / 15 / 21,1; например, 9 / 12 / 18).
- Поле «своя дистанция» для любого значения; «+» сохраняет его как новый чип; чип удаляется долгим нажатием / правым кликом.

### 3.1 Дом, выходы и подводка
- Пользователь задаёт «дом» и один или несколько **выходов** (например, двор с выходом в переулок и западный выход).
- Кольцо стартует не обязательно у дома: генератор для каждого маршрута сам выбирает выход и **подводку** —
  путь от выхода до старта кольца, по которому бегут туда и обратно.
- Длина подводки ≤ **1000 м** (настраивается). Подводка ×2 входит в километраж и в покрытие.
- Пользователь может вместо этого сам указать точку старта кольца.

### 3.2 Кольцо без повторов
- По умолчанию кольцо — простой цикл: ни одна улица не проходится дважды.
  Обе стороны улицы и тротуары вдоль неё считаются **одной улицей**.
- Опция «разрешить повторы» возвращает прежнее поведение. Подводка от правила освобождена.

### 3.3 Направление и районы
- **По компасу**: роза из 8 сторон в панели и ручка-стрелка на карте (тянется на любой угол, конус показывает сектор);
  самая дальняя точка кольца лежит в секторе. Ползунок «Точность направления»: ±15°…±60°, по умолчанию ±30°.
- **По районам** (все районы Москвы, файл `src/data/districts.json`, собирается `npm run data:districts`): слой многоугольников районов поверх карты, поиск по названию; hover — подсветка контура и лёгкая заливка
  (с анимацией), клик — выбор, можно выбрать несколько.
  - Самая дальняя точка маршрута обязана попасть в район.
  - Несколько районов — переключатель: «каждый вариант уходит в один случайный район» / «маршрут проходит через все».
  - Режим «строго»: кольцо целиком внутри объединения выбранных районов (подводка и путь до района — исключение).
    Если кольцо нужной длины не помещается — генератор честно об этом пишет, не растягивая маршрут.
  - Режим «по возможности»: в район попасть обязательно, выходить за его пределы можно.

### 3.4 Перетаскивание («верёвка»)
- Перетаскивание линии маршрута создаёт **точку притяжения**: маршрут обязан пройти через неё.
- Отпускание с Shift (на телефоне — долгое нажатие) создаёт **точку отталкивания**: круг, который маршрут обходит.
- После каждого изменения маршрут перестраивается и **подгоняется под заданную дистанцию**.
  Из найденных берётся самый похожий на прежний; если через точку нужная длина недостижима — честное сообщение с ближайшей длиной.
- Пока тянете, участок между соседними опорными точками сразу ложится по улицам (живой предпросмотр).
- Точка притяжения — карминовая «бусина»; отталкивание — пунктирный круг с «минусом», радиус 150 м, ручка на краю меняет радиус,
  круг можно сохранить как зону.
- На телефоне: долгое нажатие на линию (0,4 с) и тянуть — притяжение; долгое нажатие без движения — меню
  «Притянуть сюда / Оттолкнуть отсюда». Обычный свайп по линии двигает карту.
- На карточке — «Изменён вручную: …», «Отменить шаг» (Ctrl+Z) и «Сбросить правки».

### 3.5 Запретные зоны
- Рисуются многоугольником («+ Зона») или кругом («+ Круг»), сохраняются на устройстве.
  На карте — карминовая штриховка с пунктирным контуром; выключенная зона — серый пунктир.
- У каждой зоны переключатель «учитывать» (для временных ограничений: стройка, нечищеный парк зимой).

### 3.6 Закрытые проходы
- Пользователь отмечает на карте закрытый отрезок пути или **калитку** (точечное закрытие).
- Отмеченная калитка — маркер «круг с ×» в акцентном цвете; стандартные ворота из OSM остаются серыми.
- Закрытый отрезок — тонкая карминовая линия по улице со «шлагбаумами» на концах.
- Ворота из OSM, которые на деле открыты, можно открыть из всплывающего окна («На самом деле открыто»).
- Отметки исключаются из графа, их можно снять или переименовать в разделе «Закрытия и зоны».

### 3.7 Результаты
- Список вариантов: длина, время по темпу, % новых улиц, длина подводки.
- **«Ещё варианты»** — добавляет новые маршруты к списку, не стирая старые.
- **Звёздочка** — сохраняет маршрут в «Избранное»: переименование, показать на карте, скачать GPX.
- Название маршрута генерируется автоматически по содержанию, а не «Вариант N»:
  главный район(ы) + самый заметный объект на пути (парк, достопримечательность, крупная улица) + дистанция,
  например «Хамовники · Нескучный сад · 10,2 км». Пользователь может переименовать.

## 4. Библиотека треков (импорт GPX)

- Импорт одного или нескольких GPX. Треку автоматически даётся название по тому же алгоритму
  (дата + район(ы) + заметный объект), его можно переименовать.
- Итог импорта: всего км, **новых** км, прирост покрытия МКАД, список **объектов, встреченных на треке**
  (новые помечены).
- После импорта или удаления трека статистика покрытия **пересчитывается**.
- Ручная отметка пройденного (как в прототипе) сохраняется.

## 5. Карта покрытия (только внутри МКАД)

- Отдельный экран. Минимализм: только районы, улицы и контур МКАД.
- Районы залиты **одним цветом**, насыщенность пропорциональна % покрытия, между районами тонкие разделители;
  заливка достаточно светлая, чтобы не мешать линиям улиц. Опционально — режим «только контуры».
- Улицы: пробежанные — плотная линия цвета текста, непробежанные — тонкая бледная.
- Учитываются все пешеходные пути: улицы, переулки, дворовые проезды, парковые дорожки.
  Стороны улицы и тротуары объединяются в одну улицу.
- Улица засчитывается по участкам: участок пройден, если трек был в пределах ~20 м.
- Шапка: общий % по МКАД и «X из Y км».
- Клик по району — панель справа (на телефоне — лист снизу):
  - название, %, «X из Y км», полоска прогресса;
  - вкладки **Улицы** (список с % по каждой, сортировка), **Места** (объекты района: встречено / исследовал),
    **О районе** (справка, собранная при сборке);
  - строка вроде «самая длинная непройденная улица».
- Опционально — слой объектов на карте покрытия.

## 6. Объекты и парки

- Источник — OSM внутри МКАД, берём всё: объекты культурного наследия (`heritage`), `historic=*`,
  памятники, храмы и другие культовые места, архитектура, `tourism=attraction`, парки.
- Два уровня отметки:
  - **встречено** — автоматически по трекам: парк — трек заходил внутрь границ; точечный объект — трек прошёл
    по той улице, к которой объект относится (ближайшая улица в пределах ~60 м), т.е. объект было видно;
  - **исследовал** — ручная отметка пользователя.
- Списки с фильтрами по типу и району; статистика: сколько объектов и **парков** встречено / исследовано.

### 6.1 Данные (этап 6)

- Источник — выгрузка BBBike `Moscow.osm.pbf`; читается своим потоковым декодером (`scripts/data/pbf.mjs`).
- `scripts/data/build.mjs` собирает:
  - МКАД — внутренняя кромка по угловой выборке узлов `МКАД…`, ≈109 км;
  - районы из `src/data/districts.json`; район входит, если внутри МКАД у него ≥2 км путей;
  - «улицы» — все пешеходные пути внутри МКАД;
- Правила склейки улиц:
  - тротуары и безымянные дорожки вдоль улицы ближе 25 м (≥70% длины) присоединяются к её оси;
  - вторая полоса проспекта с тем же названием ближе 45 м — тоже;
  - ось без права прохода (`foot=no`, trunk) остаётся опорой только там, где к ней присоединились тротуары;
  - допуск улицы — 90-й перцентиль расстояния от присоединённых путей + 10 м, от 20 до 50 м;
  - безымянные пути входят в проценты, но не в список улиц.
- Объекты:
  - `heritage`, `historic=*` (без табличек), памятники, места культа, музеи, `tourism=attraction`, видовые;
  - у объекта есть улица — ближайшая в пределах 60 м;
  - парки от 1 га — многоугольниками.
- «О районе» — первый абзац ru-Википедии, до ~600 знаков.
- Формат:
  - `index.json`: версия, дата, МКАД, районы с км и рамками;
  - `d/<id>.json`: улицы как ломаные в целых дельтах 1e-5°, упрощение 3 м, объекты, парки, справка.
- Размеры: индекс 5 КБ gzip, районы 8–58 КБ gzip. Центр плотнее: бюджет 80 КБ вместо 40.
- Покрытие считается на устройстве (`src/core/cover.js`):
  - ломаные режутся на участки ~25 м, пробы через 5 м;
  - участок пройден, если ≥60% проб ближе допуска улицы;
  - результат хранится в записи трека вместе с версией данных;
  - при новой версии все треки пересчитываются в фоне.
- `.github/workflows/data.yml` — раз в месяц и вручную:
  - скачивание, сборка, тесты;
  - проверка: ±10% к прошлому релизу и бюджеты размеров;
  - релиз `data-YYYY-MM` и запуск деплоя;
  - при ошибке — issue с отчётом.
- Деплой берёт `data.tar.gz` из последнего релиза.

## 7. Этапы

1. Перенос прототипа в Vite-модули, новый дизайн, темы и акценты, мобильная раскладка, деплой на Pages.
2. Хранилище (IndexedDB), библиотека треков, автоназвания, избранное, «ещё варианты».
3. Генератор: дом/выходы/подводка, кольцо без повторов, закрытые калитки и отрезки, запретные зоны.
4. Компас и выбор районов на карте (строго / по возможности, несколько районов).
5. Перетаскивание маршрута (притяжение / отталкивание с подгонкой дистанции).
6. Датасеты МКАД (улицы, районы, объекты, справки) + GitHub Action обновления.
7. Карта покрытия с панелью района; объекты и парки, встречено / исследовал; статистика.
